# 待办：风控应对（2026-11-21 记，先不改代码）

## 事件

- 2026-11-21：维护者在自己手机上用朋友的 JWT 帮签一次到，朋友账号随即被
  TraceInt 风控拦截（官方端提示「检测到访问行为异常，请求已拦截」）。
- 图书馆老师确认：这是「非正常渠道」触发的临时风控，**次日自动恢复**，
  已预约的座位**不会**被取消。
- 对照：维护者用自己的账号、自己的手机自用一整天，无任何异常。

## 平台背景

- TraceInt 约 2026-10-28 起新增脚本检测：同类项目 EJianZQ/IGoLibrary #41、
  VenenoSix24/igolib-ldu #51 同日有人报告失效，igolib 作者表示暂时没办法。
- 截至 2026-11-21，GitHub 上无公开绕过方案。本项目不尝试对抗检测（见文末红线）。

## 原因判断（推断，未证实）

1. **主因：token 在他人设备/IP 上使用。** JWT 在朋友微信里生成，请求却从
   维护者手机发出，设备与网络环境与凭证来源不一致，符合「代签」特征。
   本人同机自用没事，是目前最有力的对照证据。
2. **次因：请求节奏偏机器。** 签到码轮询 5 秒一次，官方前端是 9 秒
   （MainActivity 轮询处注释写明是故意调快的）；打开凭证时 currentUser、
   预约、签到信息连发，也比真人操作密。

## 待办（下次改版时一起做）

1. 轮询间隔 5 秒 → 9 秒以上，与官方前端对齐（MainActivity 签到页
   `delay(5000)` 处；顺手改掉那句「更跟手」的注释）。
2. 打开/切换凭证时放缓请求节奏：几个查询串行化并加小间隔，不要连发。
3. README 与 App 内提示修正：现在 README 写着「不绑设备，凭证在谁的手机上
   都能用」——技术上能用，但有风控代价。改为推荐**本人在自己设备上使用
   自己的凭证**，并注明替他人签到（跨设备用 token）可能触发临时风控。
4. 观察项（先不动）：UA 写死 Pixel 7 / Android 13 / 微信 8.0.49 与真实设备
   不一致、OkHttp 的 TLS 指纹与微信内置浏览器不同。若以后自用也被风控，
   优先排查这两项。

已实现、无需再做的：签到成功后轮询已立即停止（PollResult.Signed → break）。

## 红线

- 不做绕过/对抗平台检测的功能；账号是实名学籍账号，代价不对等。
- 账号被风控期间不要反复重试请求，等次日自动恢复即可。
